A loading dock has crates with distinct positive weights listed in the array weights. A pallet must carry

a set of crates whose weights add up to exactly target, using each crate at most once. Return

every such set. Present each set as its weights in increasing order, and list the sets in lexicographic

order (compare the first weights, then the second, and so on, with a shorter set coming before a

longer one that starts the same way). Return an empty array when no set matches. An empty set

matches a target of 0.

2 + 3 + 5 and 3 + 7

both reach 10. The set starting with 2 comes first.

No combination of 4 and 6 reaches 5.

Choosing crates in increasing order and only from positions after the last choice generates every set exactly

once and already sorted, and a crate heavier than what remains can be skipped along with everything after

it.

Sort the weights. Recursively choose the next crate from a start index onward while it fits in the

remaining target. Record a set when the remaining target hits zero. Because choices are made in increasing

order, the results appear in lexicographic order without a final sort.

I sort the weights and backtrack with a start index so each crate is used at most once

and each set is built in increasing order. The loop stops

as soon as a weight exceeds the remaining target, since all later weights are larger too. Depth-first order

over sorted weights yields the sets lexicographically, so no post-sort is needed.

For sorted [2, 3, 5, 7] and target 10, choose 2, then 3, then 5: remaining hits 0

and [2, 3, 5] is recorded.

Backtracking tries 2 + 3 + 7 (too heavy), 2 + 5 (remaining 3, but 7 is too

heavy), 2 + 7 (remaining 1, nothing fits).

Starting with 3: 3 + 5 leaves 2 with no fit; 3 + 7 hits 0 and [3,

7] is recorded. Starting with 5 or 7 finds nothing.

O(n * 2^n) counting the copy of each recorded set, typically far less due to pruning. O(n) recursion

depth beyond the output
