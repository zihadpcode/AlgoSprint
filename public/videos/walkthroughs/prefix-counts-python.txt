A search box suggests completions from a dictionary. Given the array words, where each entry is a lowercase

word that may repeat, and the array queries of lowercase prefixes, return an array where entry i is

how many entries of words start with queries[i]. A word counts once per occurrence in words, and every

word starts with the empty prefix.

Three words start with ap, two with ban, two with

b, none with c, and all five with the empty prefix.

Both copies of tea and the word team start with

tea; only team starts with team; nothing starts with teams.

Every word that starts with a prefix passes through the trie node at the end of that prefix,

so counting arrivals at each node answers every prefix query.

Insert each word into a trie, incrementing a counter at the root and at every node along the

word's path. For each query, walk the trie letter by letter; return 0 if a letter is missing,

otherwise the counter at the final node.

I build a trie where each node stores how many inserted words pass through it. Insertion touches one

node per letter, and a query walks its letters and reads the counter where it stops, or returns

zero if the path breaks. The work is linear in the total input length, and shared prefixes are

stored once. Maps as child tables keep the memory proportional to the letters actually used.

For the first example, inserting apple, apply and apt makes the node for ap count 3.

banana and band make the node for ban count 2 and the node for b count 2; the

root counts 5.

Query c finds no child at the root and returns 0, and the empty query returns the root

count 5.

O(total word length + total query length). O(total word length)
