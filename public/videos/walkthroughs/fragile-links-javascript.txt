A data center has hubs numbered 0 to hubs - 1 joined by two-way cables in links (at

most one cable per pair, never a hub to itself). A cable is fragile if cutting it alone

would split some pair of hubs that can currently reach each other. Return every fragile cable as [smaller

hub, larger hub], sorted by the first hub and then the second.

The triangle 0-1-2 survives any single cut,

but cutting [1, 3] isolates hub 3.

The only

cable is fragile.

A tree cable is a bridge when the child's subtree has no back cable reaching the parent or

above, which the low values capture.

DFS from every unvisited hub, assigning order and low. For each neighbor other than via the arrival cable:

if unvisited, recurse, then low[u] = min(low[u], low[v]) and report the cable if low[v] > order[u]; if visited,

low[u] = min(low[u], order[v]). Sort the bridges.

A cable is a bridge iff it lies on no cycle. In a DFS tree every non-tree cable

closes a cycle, so I compute low[u], the earliest discovery time reachable from u's subtree with

one back cable. A tree cable (u, v) is a bridge exactly when low[v] > order[u]. One DFS

gives O(n + m). For very deep graphs I'd make the DFS iterative to avoid stack limits.

DFS 0 → 1 → 2. The back cable 2–0 gives low[2] = 0, which flows up: low[1]

= 0.

From 1, visit 3: low[3] = order[3] = 3 > order[1] = 1, so [1,3] is a bridge.

low[2] = 0 is not greater than order[1], and low[1] = 0 is not greater than order[0], so

those cables are not bridges.

O(n + m) plus sorting the bridges. O(n + m)
