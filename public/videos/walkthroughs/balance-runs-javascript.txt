A bookkeeper lists daily balance changes in changes; values may be negative. Count the runs of consecutive days

whose changes add up to exactly target. Runs are counted by position, so two different runs with the

same values both count.

[1, 2], [3], [3, -2, 2] and [2, 3, -2] each sum to 3: four runs.

Days 1–2 and days 2–3.

A run ending here hits the target exactly once for every earlier prefix equal to the current prefix

minus target.

Track the running prefix. For each day, add the count of (prefix - target) from the map, then

record the current prefix. Start the map with {0: 1}.

A run's sum is a difference of two prefix sums. For each day I look up how many

earlier prefixes equal the current prefix minus the target, using a hash map of prefix counts. Seeding the

map with the empty prefix and looking up before inserting are the two details that matter. It's linear

time and works with negative values, which a sliding window can't handle.

Prefixes: 1, 3, 6, 4, 6; seen starts {0:1}.

At 3: 3 - 3 = 0 is seen once, count 1. At 6: 6 - 3 =

3, count 2. At 4: 1, count 3. At 6: 3, count 4.
